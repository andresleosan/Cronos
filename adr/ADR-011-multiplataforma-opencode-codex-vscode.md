# ADR-011: Núcleo agnóstico + adaptadores para OpenCode, Codex CLI y VS Code (GitHub Copilot) — reabre parcialmente ADR-007

**Estado:** aceptada (nueva en v4.0.0)
**Fecha:** 2026-08-03

## Contexto

`ADR-007` (v3.0.0) eliminó `adapters/` y declaró uso exclusivo de OpenCode, revirtiendo `ADR-005`/`ADR-006` (v2.0.0). El motivo no fue una preferencia por OpenCode en sí, sino evidencia empírica: de los adaptadores que `ADR-005` proponía (OpenCode, Claude Code, Codex CLI, Roo Code), **solo el de OpenCode llegó a verificarse contra un runtime real** — los demás quedaron como borradores sin uso. Mantener esa superficie tenía costo de mantenimiento real y beneficio nulo.

Desde entonces, tres pedidos externos de volver a multiplataforma fueron evaluados y descartados sin reabrir `ADR-007`: `ADR-008` (Cronos Omega V5, julio 2026), `ADR-009` ("Los Titanes Enterprise V4.0", que pedía explícitamente OpenCode + Claude Code + Codex CLI + Roo Code + Cursor — un día después de que Roo Code cerrara, ver R-009), y `ADR-010` (framing multiagente de una cuarta propuesta). Los tres compartían el mismo patrón: propuestas especulativas de "escalar" el kit hacia una cobertura amplia y nominal, sin un usuario real detrás de la necesidad. `ROADMAP.md` dejó escrito el criterio: volver a adaptadores multiplataforma "no es un experimento reversible sin nueva decisión deliberada".

**Este pedido es distinto en el punto que importa:** viene directamente del operador que mantiene y usa el kit, con necesidad ya evidenciada — existe un fork paralelo (`TitanesLiteCodex`, un kit basado en Cronos construido aparte específicamente para Codex CLI) porque este kit no cubría esa plataforma. Esa duplicación es, en sí misma, exactamente el tipo de riesgo que `RIESGOS.md` categoriza como "duplicidad / deriva arquitectónica": dos kits con la misma filosofía divergiendo con el tiempo. Además, a diferencia de julio de 2026 (cuando se escribió `ADR-005`), hay ahora evidencia pública verificable de que `AGENTS.md` (bajo la Agentic AI Foundation / Linux Foundation) y el formato `SKILL.md` ("Agent Skills") se consolidaron como estándares abiertos leídos nativamente por OpenCode, Codex CLI y GitHub Copilot — lo que en 2026-07 exigía un adaptador pesado por plataforma (traducir toda la regla a mecánica propia) hoy exige uno mucho más delgado (la mayoría del contenido ya es portable de fábrica).

Verificación de esta ronda, mismo criterio que ya aplicó `ADR-005` a Roo Code: se confirmó por documentación pública (agosto 2026) el estado actual de `opencode.json`, `.codex/config.toml` y la configuración de GitHub Copilot en VS Code (`.github/copilot-instructions.md`, `AGENTS.md`, `.vscode/mcp.json`, selector de modelos con BYOK). **Ninguna verificación de esta ronda se corrió contra una sesión real con credenciales de modelo** — es investigación de documentación pública, mismo estándar de honestidad que ya usa `LOOPS.md` para el ecosistema de plugins de OpenCode. El adaptador de OpenCode no se tocó en su mecánica ya verificada (`docs/AUDITORIA-10-10-verificacion-R002.md` sigue vigente sin cambios).

## Decisión

1. **Se reabre únicamente el punto 3 de `ADR-007`** (eliminación de `adapters/`, uso exclusivo de OpenCode). **El punto 1 de `ADR-007` no se toca**: Cronos sigue siendo un único agente, `mode: primary`, con el mismo ciclo de autocrítica — nadie pidió volver a multiagente, y este ADR no lo reabre. Tres pedidos anteriores mezclaban ambas cosas (multiagente Y multiplataforma) bajo el mismo framing "enterprise"; este es explícitamente solo lo segundo.
2. **Núcleo agnóstico de plataforma** (sin cambios de fondo, sigue viviendo en la raíz del kit): `AGENCY.md`, `MASTER_PROMPT.md`, `SKILLS.md`, `MODELOS.md`, `LOOPS.md`, `skills-custom/*` — el contenido de qué hace Cronos y con qué criterio no cambia con la plataforma. Se agrega `AGENTS.md`, punto de entrada universal que las tres plataformas cargan de forma nativa (verificado por documentación, ver Contexto), con las reglas de oro condensadas embebidas inline como defensa en profundidad (mismo criterio que `ADR-003` ya aplicó cuando la duda era si `instructions` llegaba a un subagente — acá la duda equivalente es si cada plataforma resuelve `AGENTS.md`/`instructions` de forma confiable).
3. **`adapters/<plataforma>/`** vuelve a existir, con exactamente 3 subcarpetas — no una lista abierta: `opencode/` (el `opencode.template.json` existente, movido tal cual, sin cambios de mecánica), `codex/` (`config.toml.template`, nuevo), `vscode/` (`copilot-instructions.template.md` + `mcp.template.json`, nuevo). Cada uno es una traducción **delgada** de las mismas reglas a la mecánica concreta de su runtime (selección de modelo, permisos/sandbox, MCP) — no una copia del núcleo.
4. **`MASTER_PROMPT.md` gana un Paso 0 de detección de plataforma**, fusionado con la detección de situación que ya existía (no dos pasos separados — lección directa de la crítica de `ADR-006`: un paso de detección que además decide qué adaptador mecánico usar en A3/B3/7.1 tiene valor real desde el primer momento, a diferencia de 2026-07-12 cuando solo había un adaptador verificado).
5. **`MODELOS.md` Paso 1 (descubrimiento) se ramifica por plataforma** — el Paso 2 (criterio por fase) y el Paso 3 (recomendar, no decidir solo) no cambian, porque ya eran agnósticos de plataforma desde `ADR-002`. Ninguna de las tres plataformas restringe qué proveedor/modelo se puede usar: OpenCode ya era agnóstico (`opencode models`); Codex CLI acepta cualquier proveedor compatible vía `model_providers` (no solo OpenAI); VS Code/Copilot resuelve esto en vivo desde el selector de modelos del Chat, con BYOK para cualquier proveedor con clave propia. `scripts/elegir-modelo.sh` se actualiza para detectar qué configuración de plataforma existe en el proyecto y operar sobre la que corresponda, sin restringir el valor a una lista fija en ningún caso — confirmado por lectura del script, no solo por diseño (ver Consecuencias).
6. **`LECCIONES.md`** (memoria evolutiva mutable, a diferencia del resto del núcleo que es estático) gana un home nuevo, neutral de plataforma: `~/.cronos/LECCIONES.md`, en vez de vivir solo dentro de `~/.config/opencode/cronos/`. Evita que usar más de una plataforma trabaje sobre dos memorias divergentes. `scripts/instalar-global.sh` la crea ahí independientemente de qué plataforma(s) se instalen.
7. **`scripts/nuevo-proyecto.sh` y `scripts/adoptar-proyecto.sh`** copian, además del archivo de configuración de cada plataforma detectada/elegida, una copia local del núcleo a `.cronos/` dentro del propio proyecto (`AGENCY.md`, `MASTER_PROMPT.md`, `SKILLS.md`, `MODELOS.md`, `LOOPS.md`, `skills/`) — necesario porque, a diferencia de OpenCode y Codex CLI (que sí tienen un mecanismo de instalación global verificado que se fusiona con lo del proyecto, ver `docs/AUDITORIA-10-10-verificacion-R002.md`), GitHub Copilot en VS Code no tiene un archivo de instrucciones global equivalente y confiablemente scripteable — solo configuración por workspace. Esto modifica el Principio 6 de `AGENCY.md` ("los componentes globales viven fuera del proyecto"): pasa a tener una excepción explícita y documentada para el subconjunto que debe ser autosuficiente por proyecto. `scripts/actualizar-proyecto.sh` sincroniza también `.cronos/` para que esta duplicación deliberada no derive — mismo mecanismo que ya usa para `opencode.json`/`.gitignore`, extendido.
8. **Nombres de plataforma, con la lección de R-009 aplicada, no ignorada:** este ADR nombra 3 plataformas concretas (no una lista abierta "y las que vengan"), con necesidad real confirmada para las 3 — a diferencia de `ADR-005`, que se comprometió a 4 nombres sin ese filtro y perdió uno (Roo Code) antes de terminar de escribirse. Si alguna de las 3 deja de existir o cambia de mecánica de forma incompatible, se retira o corrige *ese* adaptador puntual sin afectar a los otros dos ni reabrir este ADR — son independientes entre sí por diseño (punto 3).
9. `VERSION`: `3.4.0` → `4.0.0`.

## Alternativas consideradas

- **Mantener "Solo OpenCode" y dejar `TitanesLiteCodex` como el camino oficial para Codex CLI.** Descartado — perpetúa la duplicidad ya identificada en el Contexto (dos kits con la misma filosofía, divergiendo con el tiempo) en vez de resolverla; el propio `RIESGOS.md` ya trata la duplicidad como categoría de riesgo cuando aparece dentro de un proyecto (R-010 histórico), y no hay razón para tratarla distinto solo porque ahora está entre dos proyectos separados.
- **Reconstruir el patrón completo de `ADR-005`** (lista abierta de plataformas, incluyendo nombres sin necesidad confirmada). Descartado — repetiría el error puntual que `ADR-005` ya cometió con Roo Code: comprometerse a cobertura nominal en vez de rigor verificado. Este ADR limita el alcance a las 3 plataformas con necesidad real hoy.
- **Reabrir también el punto 1 de `ADR-007`** (volver a multiagente) ya que se está reabriendo el punto 3. Descartado explícitamente — nadie lo pidió, y `ADR-008`/`ADR-009`/`ADR-010` ya dejaron tres veces por escrito por qué la arquitectura de agente único con `self-critique-loop` se mantiene. Reabrir algo que no se pidió, solo porque el archivo ya está abierto, es el mismo tipo de scope creep que esos tres ADRs rechazaron.
- **Copiar el núcleo completo dentro de cada proyecto para las 3 plataformas por igual** (no solo como respaldo de VS Code). Descartado — para OpenCode y Codex CLI ya existe un mecanismo de instalación global verificado (o verificable por documentación) que se fusiona con el proyecto sin duplicar nada; forzar la copia local ahí también multiplicaría mantenimiento sin necesidad. La copia a `.cronos/` se limita a ser el respaldo que sí hace falta para que un proyecto funcione de forma autosuficiente en cualquiera de las 3, con sincronización explícita vía `actualizar-proyecto.sh` para que no derive.
- **Esperar a tener verificación empírica real (sesión con credenciales) en Codex CLI y VS Code antes de entregar esto.** Descartado para esta versión — el mismo criterio que ya aplicó `LOOPS.md` desde v1.5.0: investigación de documentación pública, con las fuentes y la fecha declaradas, es preferible a no dar ninguna guía mientras se espera esa verificación, siempre que quede marcado con la misma honestidad ("no corrido contra sesión real") que el resto del kit ya exige. La verificación empírica queda como pendiente explícito en `ROADMAP.md`.

## Consecuencias

- **Estructura de archivos:** `opencode.template.json` se mueve de la raíz a `adapters/opencode/opencode.template.json` (contenido sin cambios de mecánica). Nuevo: `AGENTS.md` (raíz), `adapters/codex/config.toml.template`, `adapters/vscode/copilot-instructions.template.md`, `adapters/vscode/mcp.template.json`, `adapters/README.md`, más un `README.md` corto por adaptador.
- **`RIESGOS.md`:** R-008 se reabre (estaba cerrado como "decisión deliberada, no riesgo" — sigue siendo una decisión deliberada, pero la decisión cambió; se documenta el nuevo estado, no se pretende que nunca estuvo cerrado). R-009 se referencia como lección ya aplicada (punto 8 de este ADR), no se reabre. Nuevas entradas: adaptadores de Codex CLI/VS Code sin verificación empírica de sesión real (mismo tipo de brecha que ya tiene R-002, pero para mecánica nueva); posible drift entre las 3 copias de configuración de un mismo proyecto si `actualizar-proyecto.sh` no se corre.
- **`ROADMAP.md`:** el ítem "Adaptadores multiplataforma" sale de "Descartado / fuera de alcance" (donde estaba desde `ADR-009`) y se documenta como incorporado en v4.0.0, con la verificación empírica pendiente listada explícitamente.
- **`GOBERNANZA.md`:** sin cambios a la matriz RACI — "Cambio de modelo recomendado" y "ADR nuevo o cambio de stack" ya asignaban Arquitecto técnico como responsable/aprobador, que es exactamente el sombrero bajo el que se tomó esta decisión.
- **Sin cambios a la clasificación de proyectos por nivel, al ciclo de autocrítica, ni a `skills-custom/*` en su contenido de criterio** (solo se documenta, en `SKILLS.md`, que el formato ya es portable de fábrica).
- Precedente para un futuro quinto pedido de "más plataformas" o de "volver a multiagente": este ADR deja escrito que ambas preguntas son independientes — una puede reabrirse sin la otra, y reabrir esta no reabre esa.
